# Security Policy

NinjaReviews handles configuration and access to external APIs, so security issues should be reported responsibly.

## Supported versions

Security fixes are generally focused on the latest version available in the `main` branch and on the latest published release.

Older releases may not receive security fixes.

## Reporting a vulnerability

Please do not publicly disclose an unpatched security vulnerability in a GitHub Issue, Pull Request, discussion, or other public channel.

Use the private security reporting facilities provided by GitHub for this repository when available.

When reporting a vulnerability, please include:

- a clear description of the issue;
- the affected file or component;
- steps to reproduce the problem;
- the potential impact;
- any suggested mitigation or fix, if known.

Please do not include real API keys, credentials, customer information, or other sensitive data in the report. Use redacted or synthetic examples.

## What should be reported privately?

Examples include:

- authentication or authorization bypasses;
- API key or credential exposure;
- remote code execution;
- injection vulnerabilities;
- sensitive data exposure;
- installer vulnerabilities that could compromise a deployment;
- security issues that can affect other users or installations.

For ordinary bugs that do not create a security risk, please use a regular GitHub Issue.

## Disclosure

Please allow reasonable time for the issue to be investigated and, where appropriate, fixed before public disclosure.
